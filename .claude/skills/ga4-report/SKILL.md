# GA4 독자 리포트

이 리포트의 목적은 저자의 커리어에 도움이 되는 판단이다. 2026-10-14에 커리어를 "고정 독자층"으로 정했으므로, 첫 화면은 **고정 독자가 늘고 있는지, 누가 고정 독자가 되는지, 그들이 무엇을 읽는지, 그래서 다음에 무엇을 쓸지**에 답한다. 사용자, 세션, 페이지뷰 같은 트래픽 총량은 크롤러와 스팸에 흔들리므로 진단 부록으로 내린다.

GA4 Data API에서 실측 데이터를 뽑아 **기존 아티팩트 URL을 업데이트**한다. 새 아티팩트를 만들지 않는다.

- 아티팩트 URL: `https://claude.ai/code/artifact/8a232bc5-0bb9-439b-868e-91e0eead2066`
- favicon: `📈` (변경 금지), 제목: `yceffort 성과 리포트` (유지)
- 이 세션이 해당 아티팩트를 발행한 적이 없으면 `Artifact action:"read"`로 게시본을 받은 뒤 `url` 파라미터로 업데이트한다.

## 절차

### 1. 데이터 조회

```bash
node .claude/skills/ga4-report/scripts/fetch-ga4.cjs --out <스크래치패드>/ga4-data.json
```

- 기간은 ISO 주(월요일 시작)로 끊는다. 기본은 이번 4주(`--weeks 4`)와 직전 4주, 추세 26주(`--trend-weeks 26`). 28일 창은 경계만 옮겨도 증감률이 흔들린다.
- 자격증명은 `apps/blog/.env.local`에서 자동 로드된다. 없으면 실행 환경이 로컬이 아닌 것이므로 사용자에게 로컬 실행을 안내한다.
- 고정 독자용 결과: `weeklyReaders`(주별 신규/재방문, 사람 판별 + 블로그 호스트), `cohorts`(한국 + 블로그 호스트, 처음 온 주별 N주 뒤 재방문), `cohortsBySource`와 `cohortsByChannel`(같은 여덟 코호트의 처음 들어온 경로별 다음 주 재방문), `postReaders`(글별 신규/재방문, 체류), `weeklyNav`(도선 주별 본 사람/누른 사람), `totalsWeeks`(ISO 4주 트래픽 총량).
- 진단 부록용 결과: `daily`, `topPosts`, `channels`, `sources`, `referrals`, `referrerUrls`, `sourceLanding`, `landingDepth`, `countries`, `devices`, `botVisits`, `navBlocks`.

### 2. 직전 리포트 이후의 변경 확인

리포트 해석은 이 단계에서 갈린다. 숫자를 보기 전에 먼저 한다.

- **발행**: `grep -H "^date:\|^published:\|^title:" apps/blog/posts/{연도}/{월}/*.md | grep -v '\.en\.md'`. 차트 라벨은 한국어 실제 제목을 쓴다. 공개 시각은 `published: true`가 들어간 커밋이 main에 푸시된 시각이고, `gh api --paginate "repos/yceffort/blog/activity?ref=refs/heads/main&per_page=100"`로 확인한다(로컬 reflog로는 알 수 없다).
- **계측 관련 커밋**: `git log --since=<직전 리포트 날짜> -- 'apps/*/src/app/layout.tsx' 'apps/*/src/**/*Tracker*' 'apps/*/src/**/*analytics*' 'packages/shared/src/components/*'`와 `git log -S"gtag("`. 찾은 커밋은 부록의 "계측과 사이트 변경" 표와 일별 차트 `EVENTS`에 넣는다. 2026-09-11 랜딩 미상 감소도, 2026-10-16 `source` 파라미터 문제도 이 대조로 원인을 찾았다.
- **웹 푸시 구독자 수**: `gh run list --workflow notify-push.yaml`로 최근 실행을 찾고 `gh run view <id> --log | grep "done:"`의 `done: N sent`를 읽는다. 로컬 `.env.local`의 Upstash 토큰은 401이다.

### 3. 분석 규칙

**고정 독자 지표 (첫 화면)**

- 주간 재방문 독자: `weeklyReaders`의 `returning`을 주별로 보고, KPI는 이번 4주 평균과 직전 4주 평균이다. 이번 주가 집계 중이면 이틀 이상 쌓였을 때만 점선 막대(`partial: true`)로 넣고 KPI에서는 뺀다.
- 흔들림 판정: 최근 여덟 주 재방문 독자의 표준편차 SD로 `z = (이번 평균 - 직전 평균) / (SD x √(2/4))`. |z| < 2면 "흔들림 안쪽"으로 쓰고 증감으로 단정하지 않는다.
- 봄 평균 104명은 10/14에 4/13 ~ 6/14 아홉 주로 **고정한 기준선**이다(`SPRING_AVG`). 추세 창이 밀려도 다시 계산하지 않는다.
- 재방문 비율: 4주 합 `returning / (returning + new)`.
- 새 독자의 다음 주 재방문: `cohorts`에서 처음 온 주가 이번 기간 안이고 다음 주가 끝난 코호트만 쓴다(`cohortNthWeek` 0001 / 0000). 직전 값도 같은 방식.
- 경로별 재방문: `cohortsBySource`로 서피트, GitHub, 직접, 구글 막대를 만들고, `cohortsByChannel`로 "누가 데려오고 누가 남나" 비중 막대를 만든다. 리퍼럴 대 검색 차이는 두 비율 차이의 z를 함께 적는다. 표본이 10명 안팎인 경로끼리의 순서는 의미를 두지 않는다.
- 글별 고정 독자: `postReaders`를 경로(쿼리스트링과 해시 제거)별로 합쳐 재방문 수 순으로 12개. 이번 4주에 나온 글은 `inWin: true`로 표시한다(새 글은 푸시와 홈 덕에 재방문 비율이 높게 나오기 쉽다). "읽었다"까지만 말하고 "그 글 때문에 돌아왔다"고 쓰지 않는다. 독자당 체류 = `userEngagementDuration / (재방문 + 신규 사용자)`.
- 신규만 데려오는 글: 독자 40명 이상 중 재방문 35% 이하.
- 이어 읽기: `weeklyNav`의 주별 사람 수를 4주씩 더한 "누른 사람 / 본 사람". `subscribe`(10/16부터 알림 버튼 영역)는 빼고 따로 적는다.

**데이터 함정**

- **`totalsWeeks`, `totalsCompare` 행 순서를 가정하지 말 것**: `r.d[0]`의 dateRange 이름으로 고른다. 페이지뷰가 `daily` 해당 구간 합과 정확히 일치하는지로 검증한다.
- **`human_visit`은 하한이 아니라 근사치**: 두 판별 이벤트를 모두 보내지 않는 사람을 놓치는 한편, 1:1:1 크롤러 일부를 사람으로 판별한다(2026-10-19 창에서 싱가포르 104명, 중국 73명). 이들은 대부분 신규로 잡히므로 재방문 지표보다 신규와 총량에 섞인다.
- **크롤러 판별**: 사용자≈세션≈페이지뷰가 1:1:1이고 참여 세션이 거의 없으면 크롤러로 추정한다. 상시 사례는 싱가포르, 중국(10/7 이후 하루 20 ~ 30명), `/en` 랜딩. 일별 스파이크도 같은 비율이면 "크롤러 버스트 추정"으로 주석한다. 코호트는 이 때문에 한국으로 한정한다.
- **스팸**: `trafficheap.cc`(9/27 ~ 9/28, 세이셸 196세션)처럼 단일 소스가 갑자기 생기면 판별기 이벤트(human_visit, bot_visit)가 0인지 확인한다.
- **계측 단절**: 2026-08-10 SPA page_view 시작, 2026-09-11 23:50 세션 재개와 bfcache 복원 page_view(`63543e30`). 비교 기간이 이 날짜를 걸치면 페이지뷰와 랜딩별 지표에 ⚠를 단다.
- **이벤트 파라미터 `source`**: GA4가 이벤트의 `source` 파라미터를 세션 소스로 읽는다(관측, 문서 미확인). 10/16 이후 `post_end`, `tweaks`가 세션 소스로 보이면 이 때문이다. `customEvent:source`는 미등록이라 질의하면 INVALID_ARGUMENT.
- **서피트 보정**: 서피트는 `?ref=surfit.io`를 붙여 보내지만 상당수가 Direct로 분류된다. `landingPagePlusQueryString CONTAINS ref=surfit`과 `sessionSource CONTAINS surfit`을 orGroup(합집합), andGroup(교집합)으로 직접 질의한다(상위 150행 추정 금지). 수록일은 지문이 하루 10세션 이상 처음 생긴 날로 판정한 추정이고, 수록 시점은 예측하지 않고 기록만 한다.
- **집계 중인 오늘**: 일별 차트 마지막 날은 툴팁에 "(집계 중)"이 붙는다. 당일 오후에도 대부분 미처리 상태일 수 있다.
- **존재하지 않는 경로**(LLM, 크롤러 추측 링크)는 본문 표에서 빼고 각주로만 언급한다. `published: false` 초안은 프로덕션에서 서빙되지 않아 조회가 없으며, 표에서 빼고 각주로만 언급한다.

### 4. 리포트 작성

**시작점**: `Artifact action:"read"`로 받은 게시본 파일이 최신이다. 게시본에 붙는 플랫폼 래퍼(`<!doctype html>...<body>` 접두)는 벗기고 `<title>`부터 시작하는 원본 형태로 다시 게시한다. 게시본을 쓸 수 없으면 이 디렉토리의 `template.html`(2026-10-19 판)을 스크래치패드로 복사해 시작한다. 디자인 토큰과 차트 코드는 유지하고, 다음만 갱신한다.

1. **헤드라인**: 그 기간의 가장 큰 고정 독자 발견 한 문장(매번 변주). 트래픽 총량 변화는 헤드라인에 쓰지 않는다.
2. **KPI 4타일**: 주간 재방문 독자, 재방문 비율, 새 독자의 다음 주 재방문, 웹 푸시 구독자. 각 직전 4주 대비.
3. **요약 3줄**(lede).
4. **고정 독자 추세 (26주)**: `WEEKLY`(`w`, `mon`, `ret`, `neu`, `pub`, 필요하면 `partial`), `WEEK_NOTES`. 발행 수는 frontmatter `date`를 주별로 센다(연도를 꼭 거를 것, 월/일만 키로 쓰면 2020년 글이 섞인다). 콜아웃에 이번 기간을 해석하되, 결과를 본 뒤 고른 비교는 판정에 쓰지 않는다고 밝힌다.
5. **처음 어디서 온 사람이 돌아오나**: `COHORT_CH`와 비중 막대 두 줄(HTML에 폭이 박혀 있음).
6. **고정 독자는 어떤 글을 읽나**: `LOYAL`, `ONEOFF`, 이어 읽기 표(HTML).
7. **다음 글 후보 2 ~ 3개**: 후보마다 `데이터 근거`, `흥미 기준`, `출처`, `사실과 추정`을 나눠 적는다. 출처는 메모리의 보류 글감, 진행 중인 시리즈 초안, 집필 중인 책(『Node.js Deep Dive』, 『웹 성능 Deep Dive』)이다. 데이터가 후보에 불리하면(예: 10/8 번들러 글의 낮은 재방문) 숨기지 말고 적는다. 마지막에 "우선순위를 낮출 쪽"을 한 줄로 쓴다. 루트 `CLAUDE.md`의 블로그 포스트 전략과 메모리의 글쓰기 피드백을 따른다.
8. **미뤄 둔 판정**: 이전 리포트들이 사전 등록한 기준을 **그때 적은 그대로** 대 본다. 기한 전이면 중간값과 기한만 적고, 기한이 지난 것은 판정한다. 새 기준이 생기면 다음 리포트에서 볼 수 있게 숫자와 날짜를 박아 적는다. 기준을 바꿔야 하면 바꾼 이유와 새 경계를 함께 남긴다.
9. **진단 부록**(`details.appendix`, 기본 접힘): 트래픽 KPI 표(사람 판별, 크롤러 제외 값 포함), 크롤러와 스팸 콜아웃, 일별 트렌드(`DAILY`, `EVENTS`), 인기 글(`TOP_POSTS`), 채널(`CHANNELS`, 서피트 보정 문장), 도선 주별(`NAV`), 이번 기간의 계측과 사이트 변경 표.
10. **각주**: 데이터 생성 시각, 지표 정의, 검증 방법, 확인하지 못한 것.

**하드코딩된 값**: 막대 최댓값은 `maxOf`로 자동 계산된다. 대신 비중 막대 두 줄의 `width`와 라벨, 이어 읽기 표, 판정 표, 트래픽 KPI 표는 HTML에 직접 쓰므로 데이터와 함께 고친다. `SPRING_AVG`는 바꾸지 않는다.

### 5. 검증과 게시

- 브라우저로 라이트, 다크, 모바일 폭 렌더링을 확인한다. 로컬 미리보기는 래퍼를 벗긴 파일이라 `<meta name=viewport>`를 미리보기에만 붙이고, 부록 `details`를 열어 둔 사본도 함께 본다.
- chrome-devtools MCP의 브라우저 프로필을 다른 세션이 쓰고 있으면 죽이지 말고, 헤드리스 Chrome Beta를 별도 `--user-data-dir`로 실행한다(`--virtual-time-budget`, `--screenshot`, `--dump-dom`). 헤드리스 창 폭은 최소 500px이고, 스크롤한 뒤의 스크린숏은 빈 화면이므로 긴 창으로 찍고 `ffmpeg -vf crop`으로 자른다. macOS에는 `timeout` 명령이 없다.
- 게시 전 `Artifact action:"read"`로 게시본을 받고, 저장된 파일을 Read 도구로 전부 읽어야 publish가 통과한다(1회 25,000토큰 제한이 있으므로 offset/limit로 나눠 읽는다). 거절되면 read를 다시 한 뒤 게시한다.
- 게시 label에는 날짜를 적는다(예: `2026-10-19`). icon은 재게시 때 넘기지 않는다.
- 같은 데이터로 자주 돌리면 직전 리포트와 대부분 겹친다. 최소 일주일 간격을 권하고, 겹친 일수를 헤더 배지에 적는다.

### 6. 톤

리포트 본문은 합니다체. 단정 대신 "추정됩니다", "여지가 있습니다" 수준의 겸손한 설명형. 원인을 지목할 때는 후보를 모두 적고 몇 개를 확인했는지(예: 0/3) 밝힌다. em dash, en dash, 가운뎃점은 쓰지 않는다.
