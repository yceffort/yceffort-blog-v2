# PWA 전용 오프라인 저장과 "저장한 글" 페이지

작성일: 2026-10-19. 기준 ref: main 357ea7ad (`apps/blog/public/sw.js` CACHE_VERSION `v4`).

## 의도

블로그를 PWA로 설치한 독자가 지하철처럼 인터넷이 불안한 곳에 가기 전에 글을 미리 받아 둘 수 있게 한다. 오프라인 저장은 PWA에서만 한다. 브라우저로 들어온 독자에게는 저장하지 않는다.

배경: 지금은 브라우저든 PWA든 방문한 글을 서비스 워커가 자동으로 저장한다. 2026-08-29 랩 측정에서 이 저장(`savePageHTML`)이 글 클릭 1회 구간의 트래픽을 +79% 늘렸다(서비스 워커 캐싱 3편). 저장을 원하는 독자(PWA 설치자)에게만 그 비용을 쓰고, 대신 그 독자에게는 최근 글 자동 저장이라는 기능을 준다.

## 목표

1. PWA(설치된 앱, standalone)에서 연 글만 오프라인에 저장된다.
2. PWA에서 "최근 글 자동 저장"을 켜면 최근 N편을 미리 받는다. 기본값 5편, 선택지 끄기/5/10/20.
3. PWA에서만 보이는 "저장한 글" 페이지에서 저장된 글 목록을 보고 개별 삭제, 전체 삭제, 자동 저장 설정을 바꿀 수 있다.
4. 저장한 글과 "저장한 글" 페이지 자체가 오프라인 PWA에서 열린다.

## 비목표

- research 사이트는 대상이 아니다. research의 수동 저장 구조(`apps/research/src/components/offline/`)는 그대로 둔다.
- 브라우저 독자의 기존 오프라인 캐시를 지우지 않는다. `CACHE_VERSION`을 올리지 않는다. 올리면 PWA 사용자의 캐시도 함께 지워진다.
- 서비스 워커 캐싱 시리즈 글(`apps/blog/posts/2026/08/service-worker-caching-*.md`) 본문 수정은 이번 범위가 아니다. 2편은 "방문한 페이지는 자동 저장"하는 v4 구조를 설명하므로 이 변경 뒤 실제 동작과 어긋난다. 고칠지는 사용자가 따로 판단한다.
- GA4 이벤트 추가는 하지 않는다.

## 반목표 (기술적으로 동작해도 실패로 보는 것)

- 브라우저 독자에게 글 HTML이나 본문 이미지를 위한 추가 요청이 하나라도 나가는 것. 3편에서 측정한 클릭 1회 구간의 요청 수와 바이트(워커 없음 기준 36요청, 317,702B)보다 늘면 실패다.
- 브라우저 독자에게 "오프라인에 저장됨" 토스트나 "저장한 글" 링크가 보이는 것.
- 웹 푸시가 깨지는 것. 구독, 수신, 알림 클릭이 지금처럼 브라우저와 PWA 양쪽에서 동작해야 한다.
- 사용자가 ✕로 지운 자동 저장 글이 다음 실행 때 다시 받아지는 것.

## 제약

- 서비스 워커는 브라우저에서도 등록돼 있어야 한다. 글 끝의 웹 푸시 알림 버튼이 같은 `sw.js`(`push`, `notificationclick` 핸들러)에 의존한다.
- 서비스 워커는 요청이 PWA 창에서 왔는지 브라우저 탭에서 왔는지 알 수 없다. FetchEvent와 Clients API(WindowClient)에 display-mode 정보가 없다. 내비게이션 요청은 응답이 나가기 전까지 페이지 코드가 돌지 않는다. 따라서 "저장할지"는 페이지 쪽에서 판단해야 한다: `matchMedia('(display-mode: standalone)')`, iOS는 `navigator.standalone`도 함께 본다.
- 저장소 공유: Android와 데스크톱 Chrome은 설치된 PWA와 브라우저 탭이 같은 오리진 저장소를 쓴다. 그래서 PWA에서 저장한 글이 같은 기기의 브라우저 탭에서도 오프라인으로 열릴 수 있다. 이것은 허용한다. iOS 홈 화면 앱은 Safari와 저장소가 분리돼 있다.
- 서비스 워커 안에는 DOMParser가 없다. 목록 데이터는 JSON으로 받는다.
- 외부 도메인 본문 이미지는 no-cors opaque 응답으로 저장되고, Chrome은 quota 계산에서 이를 크게 부풀린다(1편 측정 104KB가 6.6MB). 자동 저장의 이미지 비용이 큰 이유다(처음엔 기본 꺼짐이었으나 2026-10-20 사용자 지시로 기본 켜짐).
- `/en/saved`는 `apps/blog/src/proxy.ts`의 `EN_PREFIXES`에 `saved`를 넣지 않으면 404로 rewrite된다. `/saved`(한 세그먼트)는 `MULTI_SEGMENT_PREFIXES` 검사 대상이 아니라 그대로 통과한다.
- 헤더 메뉴는 `apps/blog/src/config.ts`의 `SiteConfig.menu`를 `LayoutWrapper.tsx`의 `HeaderNav`와 `MobileNav.tsx`가 각각 영문 경로로 바꿔 쓴다. 두 곳의 영문 매핑 목록이 이미 서로 다르다(헤더는 4개, 모바일은 2개). 이번 변경에서는 기존 차이를 고치지 않고 `saved` 링크만 양쪽에 맞게 넣는다.
- `ServiceWorkerRegistration`은 production에서만 렌더링된다. 검증은 `pnpm build:blog` 후 `pnpm start`로 한다.

## 사용자와 정한 것

- 저장은 PWA에서만 한다. 브라우저 독자에게는 웹 푸시, 오프라인 안내 페이지(`/offline`), JS/CSS/폰트 보관(`/_next/static/`, woff2, 폰트 호스트의 cacheFirst)만 지금처럼 남긴다. 둘 다 추가 트래픽이 없고, PWA에서 저장한 글을 오프라인으로 열려면 JS/CSS가 어차피 필요하다.
- PWA로 켜면 지금처럼 홈(`start_url: "/"`)이 뜬다. PWA일 때만 헤더와 모바일 메뉴에 저장 페이지 링크가 하나 더 보인다.
- 페이지 배치는 시안 A: 맨 위에 저장 편수와 마지막 갱신 시각, 그 아래 설정 상자("최근 글 자동 저장" 끄기/5/10/20 분할 버튼, "본문 이미지도 저장" 스위치), 그 아래 자동 저장분과 읽은 글을 한 목록에 섞고 "자동/읽음" 꼬리표로 구분한다. 항목마다 ✕, 맨 아래 전체 삭제.
- 자동 저장 기본값은 5편.
- 블로그만 해당한다.

## 동작 명세

### 브라우저 독자 (standalone 아님)

- `fetch` 핸들러는 페이지 캐시(`pages-v4`), 이미지 캐시(`images-v4`), RSC 캐시(`rsc-v4`)에 쓰지 않는다. 읽기(오프라인일 때 캐시된 응답으로 폴백)는 유지한다. 기존 캐시에 남은 글이 오프라인에서 열리는 건 괜찮다.
- 정적 자산과 폰트의 cacheFirst 쓰기는 유지한다.
- install 때의 프리캐시는 `/offline`만 남긴다. 지금은 `/`와 홈의 이미지까지 받는데(`install` 핸들러, `saveImagesFromHTML`), 이는 첫 방문 브라우저 독자에게 추가 트래픽이다. (내 판단)
- "오프라인에 저장됨" 토스트가 뜨지 않는다.
- `/offline` 페이지 문구 "이전에 방문한 페이지는 오프라인에서도 읽을 수 있습니다"는 브라우저에서는 더 이상 사실이 아니다. 앱으로 설치하면 글을 저장해 둘 수 있다는 내용으로 바꾼다. (내 판단, 문구는 구현 때 사용자 확인)

### PWA 독자 (standalone)

- 워커의 요청 경로(`fetch` 핸들러)에서는 정적 자산과 폰트 외의 캐시 쓰기를 전부 없앤다. 페이지 캐시와 이미지 캐시는 PWA 페이지가 요청할 때만 쓴다. 그래서 하드 내비게이션한 글도 HTML을 한 번 더 받아 저장한다. PWA 한정이라 이 재요청은 허용한다. (내 판단)
- RSC 캐시(`rsc-v4`)는 채우지 않는다. 오프라인 소프트 내비게이션은 RSC 캐시 미스에 503을 주면 Next 라우터가 MPA 내비게이션으로 넘어가고, 그 문서 요청을 캐시된 HTML이 받는다(v4 `handleRSC` 주석의 경로). (내 판단)
- 글을 열면(하드 내비게이션, 소프트 내비게이션 모두) 그 글의 HTML이 저장되고 "읽음"으로 기록된다. 본문 이미지는 지금의 v4처럼 HTML에서 추출해 함께 저장한다(최대 50장, `extractAssetUrls`). 2026-10-20 사용자 결정으로 `<video poster>`와 같은 오리진 `.html` `<iframe src>`(데모, 쿼리 포함, `pages-v4`에 저장)도 함께 저장하고, 저장한 데모 문서가 문서 기준 상대 경로로 참조하는 이미지도 저장한다. mp4는 제외한다. 크기 상한은 두지 않는다(처음 2MB 상한을 두었다가 "완벽히 저장" 지시로 제거). `sandbox="allow-scripts"`만 있는 iframe은 워커를 거치지 않아 캐시가 있어도 오프라인에서 안 열리므로(브라우저 확인) `LiveDemo`에 `allow-same-origin`을 추가했다(사용자 승인). 처음 저장된 글이면 지금처럼 토스트를 띄운다.
- PWA를 켤 때마다 자동 저장을 한 번 돌린다(하루 1회 제한 없음, 켜는 순간이 대개 "나가기 전에 받아 두자"는 순간이라서). "켤 때"는 PWA 문서가 하드 로드될 때(콜드 스타트와 새로고침)를 말한다. 소프트 내비게이션과 포커스 복귀는 제외한다. 한 번 돌 때 나가는 요청은 최근 글 목록 JSON 1건과 아직 없는 글뿐이다. (내 판단) 최근 N편 중 아직 없는 글만 받는다. "본문 이미지도 저장"이 꺼져 있으면 HTML만 받는다. 기본은 켜짐(2026-10-20 사용자 지시로 꺼짐에서 변경). (내 판단: 이미지 스위치는 자동 저장분에만 적용한다. 읽은 글은 읽는 동안 이미 이미지를 받았으므로 지금처럼 저장한다)
- `navigator.connection.saveData`가 켜져 있으면 자동 저장을 건너뛴다. (내 판단)
- 자동 저장분 중 새 글이 나와 최근 N편 밖으로 밀려난 것은 지운다. "읽음" 글은 남긴다. N을 줄이면 같은 규칙으로 정리한다.
- 자동 저장된 글을 열면 꼬리표가 "읽음"으로 바뀐다.
- ✕로 지운 자동 저장 글은 다시 받지 않도록 기억한다. 전체 삭제는 이 기억도 함께 지울지 구현 때 정한다(지우면 다음 실행에 최근 N편을 다시 받는다). (내 판단: 전체 삭제는 기억까지 지운다)
- 자동 저장할 언어는 그 PWA에서 마지막으로 연 쪽(한국어/영어, 경로의 `/en` 접두어)을 따른다. 언어가 바뀌면 이전 언어의 자동 저장분은 "현재 언어의 최근 N편 밖"이 되므로 밀려난 글과 같은 규칙으로 지운다. 읽은 글은 언어와 상관없이 남긴다. (내 판단)
- 저장 페이지와 홈도 오프라인에서 열려야 하므로 PWA를 켤 때마다 새로 받아 저장한다. 홈은 썸네일 이미지까지 함께 저장한다(v4가 install 때 하던 일을 PWA로 옮긴 것). 이 둘은 목록에 보이지 않는다. (내 판단) 영문일 때는 start_url `/`가 서버에서 `/en`으로 리다이렉트되므로, `/`를 `redirect: 'manual'`로 받은 opaqueredirect 응답을 `pages-v4`에 함께 저장해 워커가 오프라인에서 그 리다이렉트를 재생하게 한다(2026-10-20 최종 리뷰 반영, Chrome 확인, Safari 미확인). 한국어 쪽은 `locale=en` 쿠키가 있으면 `/` 저장이 실패하는 한계가 남는다.
- 이미 저장된 글이 수정돼도 따로 갱신하지 않는다. PWA에서 온라인 상태로 다시 열면 그때 새로 저장된다. (내 판단)
- 자동 저장마다 토스트를 띄우지는 않는다. 다만 설치 후 첫 자동 저장이 끝났을 때 한 번만 "최근 글 N편을 오프라인에 저장했습니다"를 띄운다. 기본값 5편이 묻지 않고 내려가므로 독자가 알아챌 수 있게 하려는 것이다. (내 판단)
- 페이지 캐시 상한(200)은 그대로 둔다. 상한 트리밍이 자동 저장분이나 읽은 글을 지울 수 있다는 점은 받아들인다(최근 20편 + 읽은 글이 200을 넘는 경우는 드물다고 본다, 추측).

### 저장한 글 페이지

- 경로: `/saved`, `/en/saved`. 메뉴 라벨: 기존 메뉴가 영문(`Posts`, `Series`, `Tags`)이므로 `Saved`. (내 판단)
- 브라우저에서 주소로 직접 들어오면 목록 대신 "앱으로 설치하면 쓸 수 있습니다"라는 안내만 보인다.
- 목록은 네트워크 없이 로컬 데이터만으로 그린다(오프라인에서 열리는 페이지이므로). 항목에는 글 제목과 꼬리표, ✕가 있다. 누르면 그 글로 간다.
- 목록의 기준은 페이지 캐시(`pages-v4`)에 실제로 있는 글 경로다(`/{year}/{month}/{slug}`, `/en/...`). 홈, `/saved`, `/offline`, 목록 페이지(`/pages/...`, `/tags/...` 등)는 뺀다. 메타데이터 저장소는 "자동" 꼬리표, ✕ 기억, 설정값, 마지막 갱신 시각만 담는다. 이렇게 하면 상한 트리밍이 캐시를 지워도 목록과 어긋나지 않는다. (내 판단)
- 이번 변경 전에 쌓인 글(브라우저 방문분 포함, Android와 데스크톱은 저장소를 공유하므로 PWA 목록에 보인다)은 메타데이터가 없으니 "읽음"으로 보여 준다. 제목은 캐시된 HTML의 `<title>`에서 읽는다. (내 판단)
- 정렬은 저장된 순서의 역순(최근 저장이 위)이다. 옛 글은 날짜가 경로의 연/월밖에 없어서 글 날짜순 정렬이 불가능하다. (내 판단)
- 헤더 링크는 서버 렌더링 결과와 어긋나지 않게 마운트 후 standalone을 확인하고 보여 준다.
- 저장 크기는 저장하는 시점에 잰다(글 HTML + 같은 오리진 데모 문서 + 그 문서가 참조하는 이미지 + 글의 같은 오리진 이미지). 다른 글과 공유하는 자산도 글마다 센다. 외부 이미지는 opaque 응답이라 바이트를 읽을 수 없으므로 크기에 섞지 않고 장수로 따로 보여 준다. 각 행에 그 글의 크기를, 요약 줄에 전체 합계를 보여 주고, 설정 상자 아래에는 측정된 평균으로 "한 편당 평균, 20편이면 약" 값을 추정해 보여 준다(추정이므로 "약"으로 표기). 크기 기록이 없는 자동 저장분은 다음 동기화 때 한 번 다시 받아 잰다. 2026-10-20 사용자 결정.
- 화면 문구는 한국어/영어 두 벌.

### 최근 글 목록 데이터

- 한/영 각각 최근 20편(선택지 최댓값)의 경로, 제목(`<em>` 제거), 날짜를 담은 JSON 엔드포인트가 필요하다. 빌드 시 고정되는 값이어야 한다(`apps/blog/src/utils/feed.ts`의 `buildFeedResponse`처럼 `getAllPosts(locale)`를 쓰고 요청 시점 IO를 피한다).
- 영문은 번역본이 있는 글만 들어간다(`getAllPosts('en')` 기준).

## 구현자에게 맡기는 것

- 저장 쓰기를 어디서 할지: 페이지가 `caches`에 직접 쓰는 방식과 페이지가 postMessage로 워커에 시키는 방식 모두 가능하다. 다만 기존 `savePageHTML`, `saveImagesFromHTML`, `putWithTrim`, 토스트용 `page-saved` 메시지를 재사용하는 쪽이 변경이 적다. 워커가 PWA 클라이언트 목록을 메모리에만 들고 있으면 워커가 재시작될 때 사라진다는 점을 고려할 것.
- 저장 메타데이터(꼬리표, 제목, 날짜, ✕ 기억, 설정값, 마지막 갱신 시각)를 둘 곳: IndexedDB, Cache Storage의 별도 엔트리, localStorage 중 선택. 설정값은 페이지와 워커 양쪽이 읽어야 하면 localStorage는 워커에서 못 쓴다는 점을 고려할 것.
- 최근 글 JSON 엔드포인트의 경로와 형태. `/api/` 아래에 두면 워커의 fetch 핸들러가 통과시킨다(`url.pathname.startsWith('/api/')` 분기).
- 컴포넌트 구조, 스타일(기존 StyleX 패턴을 따른다).
- 검증 방법. 참고: DevTools 오프라인 에뮬레이션은 워커 안의 `fetch()`에 적용되지 않으므로 오프라인 확인은 로컬 prod 서버를 죽여서 한다. hard reload는 워커를 우회한다. standalone 상태를 자동화로 흉내 낼 수 있는지(CDP의 display-mode 미디어 에뮬레이션 등)는 확인하지 않았다. 안 되면 localhost에서 실제로 PWA를 설치해 확인한다. research의 Playwright 오프라인 테스트(`apps/research/tests/offline.spec.ts`)가 참고 자료다.
- `apps/blog/public/` 파일만 staged된 커밋은 lefthook pre-commit의 oxlint/oxfmt가 "no files"로 실패한다. 그 경우만 `--no-verify`.
